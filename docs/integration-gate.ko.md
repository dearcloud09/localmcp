# 통합 관문 — 검토본과 실제 서버 수용의 구분

기준: 2026-09-19, 원격 `9ce1f38031696a3dda1394186bc88f2823170879`. M2c 소스는 현재 원격에 반영되지 않았다. 이번 문서는 차단된 소스를 우회 업로드하는 방법이나 배포 승인이 아니다.

## 검토 묶음
`localmcp-integration-review.zip`은 네 단계의 기존 M2c 소스를 한 기준으로 정리한 검토용 산출물이다. overlay에는 변경/추가 27개 파일, baseline에는 수정 대상 기존 7개 파일, independent에는 실행 가능한 부분 소스/컴파일 검사, reports에는 근거가 있다. 자동 적용·GitHub 쓰기·계정 연결·서버 시작 도구는 없다. 검토 전용 package.json을 실제 프로젝트에 복사하지 않는다.

현재 원격과 검증된 기준 파일이 일치하며 임시 부분 Git 저장소에서 통합 패치 적용을 확인했다. 이는 전체 clone·의존성 설치·실제 서버 통합을 대신하지 않는다. 이전 recovery 벤치마크를 해시 대조 후 포함했지만 이번에 속도를 재측정하지 않았다.

## 발견한 테스트 경로 차이
기존 독립 검사는 컴파일한 .js를 사용한다. 실제 저장소 npm test는 tsx로 .ts를 실행한다. 일부 M2c 테스트의 fork/spawn이 소스 위치에 존재하지 않는 .js를 직접 실행했다. source/compiled 모드에 맞는 실제 파일과 명시적 loader를 선택하도록 로컬에서 수정했고, Node의 원래 자식 실행 실패와 compiled 회귀를 검사했다. pinned tsx 소스 실행 자체는 아직 미검증이다.

## 수용 기준 — 순서를 생략하지 않음
1. 원격 코드 쓰기가 허용되는 경계가 확인되어야 한다. 이전 보안 차단에 대해 우회·분할·재전송을 하지 않는다.
2. 실제 저장소의 package.json과 lockfile을 유지하는 전체 checkout/의존성이 필요하다. 부분 검토 패키지로 성공 표시를 만들지 않는다.
3. 기존 verify:minimum으로 check, build, 전체 test, 실제 SDK stdio smoke를 실행한다. 새 SDK 두 suite의 12개와 source-mode 자식 실행이 포함되어야 한다. E1 보조 검사 9개는 기존 별도 검사 이력과 구분한다.
4. 새 recovery 설정·초기화·재시작·권한 변경·HTTP/stdio/Worker 수명주기를 실제 의존성으로 검증한다. 독립 Workspace/registry 시험은 이 단계의 대체품이 아니다.
5. 실제 Docker E0-D는 별도 승인된 로컬 Docker와 검토한 이미지로 실행한다. 이미지 자동 다운로드·CI 과금으로 대체하지 않는다.

## 현재 결론
독립 162개와 patch roundtrip은 통과했지만 IG-03/04/05는 미완료다. 없는 SDK를 대역으로 만들거나 실패 검사를 삭제하지 않는다. 선행조건이 없는 상태에서 제품 기능을 계속 추가하지 않고 통합 대기로 유지한다. 사용자의 이전 E0·파일-only E1 성공은 보존하되 새 검토본으로 확대하지 않는다. PR Draft·main 미병합·배포 없음.
