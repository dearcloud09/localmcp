# M2C-02b — 영속 편집 기록의 서버 연결 계약

상태: 로컬 검토본 구현·독립 검증. 원격 실행 코드에는 미반영. 기준 원격 커밋은 `e760831e1c0923be9d7b54124c6ff55399f76d05`다.

## 설정과 초기화
설정 생략 또는 memory 모드는 기존 메모리 기록을 유지한다. durable 모드에는 절대 경로 directory와 선택적인 capacity/lockWaitMs를 지정한다. 기본 용량은 1,024개, 대기 시간은 2,000ms다. 값의 타입을 강제로 변환하지 않고 잘못된 키/범위는 거부한다.

기록소 부모는 이미 존재하는 소유자 전용 디렉터리여야 한다. 모든 workspace와의 겹침 및 기록소 안의 설정 파일을 거부하고 심볼릭 링크 해석 후에도 확인한다. 이 검증은 디렉터리를 생성하거나 권한을 바꾸지 않는다.

별도 로컬 초기화 진입점은 명시적 create-only 플래그를 요구한다. 기존 디렉터리·손상된 namespace는 덮어쓰거나 재설정하지 않는다. 서버 시작은 existing-only로 열기 때문에 기록소를 잃어버린 상황을 새 빈 기록소로 바꾸지 않는다. 자동 fallback·자동 삭제·TTL 잠금 탈취는 없다.

## 런타임 연결
config에는 검증된 recovery 설정만 담고, HTTP/stdio 시작 시 RuntimeMutations를 준비한다. 이 준비는 해당 자식 서버의 하위 MCP 시작과 포트 공개보다 앞이다. 부모 에이전트의 등록/중계 수명주기는 이번에 수정하지 않았으며 그 네트워크 시작 순서까지 검증했다고 주장하지 않는다.

RuntimeSnapshot이 공유 상태를 보유하고 createServer/Workspace 선택기가 이를 사용한다. stateless HTTP가 요청마다 새 프로토콜 서버를 만들어도 같은 journal을 전달한다. 직접 embedding에서 durable 설정만 주고 런타임을 누락하면 메모리로 추정하지 않는다. workspace_info에는 모드와 보호 범위만 표시하고 저장 경로·작업 ID·영수증은 추가 노출하지 않는다.

같은 런타임에서 모드·기록소·용량·대기 시간·실제 workspace 집합이 바뀌면 설정 재로딩을 거부한다. 같은 경로의 alias 이름 변경과 순서 변경은 허용한다. 일반 권한 변경은 허용하지만, 금지된 namespace 변경과 권한 회수를 한 설정에 섞으면 전체 reload가 거부되어 마지막 유효 설정을 유지한다. 실패 로그를 무시하면 안 된다.

완료된 작업의 재전달도 공통 registry의 현재 파일 권한 검사 뒤에만 가능하다. 실행 중인 이전 호출을 소급 취소하지 않는다. 재시작 후 같은 설정/기록소의 성공 기록은 과거 영수증으로 반환하며 현재 파일 내용 확인을 대신하지 않는다.

## 검증 범위
새 독립 30개 + 이전 91개를 한 실행에서 검사해 121개 통과했다. 실제 임시 파일, 두 별도 Node 프로세스의 runtime 재열기, 삭제/손상된 기록소, 명시적 초기화, 설정 교체, 실제 공통 registry와 Workspace의 조합을 검사했다. 후자의 도구 descriptor/parser는 검사 전용이며 실제 Zod/SDK 호출 결과로 표시하지 않는다.

실제 config/Zod/MCP를 쓰는 신규 검사 7개는 작성·문법 검사했지만 실행하지 못했다. src/config.ts·src/index.ts·src/server.ts 등 연결 지점의 전체 타입/런타임 검사는 전체 저장소와 원본 의존성이 필요하다. 부분 소스의 strict 검사와 모든 연결 지점의 통합 성공은 다른 기준이다.

## 남은 한계
보호는 operationId와 expectedSha256을 제공한 텍스트 편집/행 patch에 한정된다. 원문 쓰기·삭제·이동에는 동일한 영속 작업 계약이 없다. 서로 다른 ID의 파일 잠금은 여전히 한 프로세스 범위다. 운영자 상태 조회·검토 후 복구 명령, 다중 파일 트랜잭션, 프로세스 부활, 전원 장애 내구성은 미완료다.

현재 소스는 로컬 보관본이며 Git 변경은 문서뿐이다. SDK/전체 앱/macOS/Docker 검증과 코드 반영 경계를 해결하기 전 운영 준비 완료로 보지 않는다. 기존 사용자 E0/E1 근거를 새 코드에 자동 적용하지 않는다.
