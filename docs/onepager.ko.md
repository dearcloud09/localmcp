## 목표와 구조
ChatGPT가 코딩 판단을 하고, 포크가 로컬 실행·권한·작업 기록·결과 전달을 담당한다. 모듈화가 별도 서버를 의무화하지 않는다.

`ChatGPT → MCP 입구 → 공통 코어 → 기능 모듈 → 내부 함수 / 기존 CLI / 필요한 하위 MCP`

파일 편집은 내부 코드, Git·테스트·빌드는 기존 CLI를 우선 활용한다. 전문 기능만 하위 MCP로 확장하고, 자주 쓰는 도구는 직접 노출한다. 불필요한 모델·통신·발견 호출은 늘리지 않는다.

## 현재 권한 규칙
명시적 프로젝트와 workspace 밖 설정이 필요하다. `permissions`를 생략하면 `fileRead=true`, `fileWrite=false`다. 파일 수정에는 `permissions.fileWrite=true`가 필요하고 쓰기만 허용하는 조합은 거부한다. 기존 `features.files=false`는 두 권한을 모두 끈다. 셸·프로세스는 별도 설정이며 기본 비활성이다.

파일 도구의 권한은 공통 dispatch에서 입력 해석/실행 전에 검사한다. MCP의 `readOnlyHint`나 모델의 호출 인자는 권한을 부여하지 않는다. M2a의 init/demo는 **편집 검증용**이므로 새 프로필에 읽기·쓰기를 명시한다. 이전 프로필을 자동 수정하지 않는다. [파일 권한·전환 안내](m2b-file-permissions.ko.md)

## 검증·다음 관문
**Git의 이 파일과 progress.md가 기준이고 다운로드는 스냅샷이다.** 이번 Linux/Node 22.16.0에서 독립 67개와 해당 TS strict 검사는 통과했다. 실제 SDK/config/hot reload 검사 6개는 작성했지만 미실행이며, 전체 check/build/test·기존 프로필 28개 재실행·macOS/Windows·실제 ChatGPT는 남아 있다. 이전 검사 수를 현재 전체 통과 수로 합산하지 않는다. [검증 기록](validation/m2b-file-permissions-local.json)

CI는 사용자 확인 사용 한도 초과로 보류한다. PR은 Draft이며 main 병합·공개 터널·계정/과금 변경·패키지 배포는 수행하지 않는다. 현재 권한은 서버의 파일 도구 전체에 적용하며 workspace별 권한은 별도 미구현이다. 명시적으로 켠 셸/하위 MCP와 직접 라이브러리 호출은 이 파일 권한으로 격리되지 않는다. 다음은 민감 파일·하위 MCP 경계이며 OS 격리도 미완료다. MIT 고지를 유지한다.
