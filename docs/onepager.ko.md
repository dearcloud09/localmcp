## 목표와 구조
ChatGPT가 판단하고 포크가 로컬 실행·권한·기록을 담당한다. 기능 모듈은 내부 함수·기존 CLI·필요한 하위 MCP를 사용한다. 모듈화가 별도 서버나 추가 모델을 뜻하지 않는다.

`ChatGPT → MCP → 공통 코어 → 파일 / Git / 검사 / 전문 도구`

## 확보한 E0 근거
사용자의 `88f455c` 갱신 후 로그에서 네 단계와 `MINIMUM_LOCAL_OK (Docker and live ChatGPT not tested)`를 확인하고 해당 실행기와 대조했다. 사용자 제공 결과이며 어시스턴트 재실행·GitHub CI가 아니다. report.json·단계별 로그는 미수신이므로 개수/skip·버전·dirty 상태·설치 버전 일치는 확정하지 않는다. [E0 기록](validation/e0-macos-user-report.json)

## E1의 실행 범위
[실연결 안내](e1-live-chatgpt.ko.md)의 `scripts/e1-session.mjs prepare`는 `~/.localmcp-e1`에 새 파일-only 샘플·외부 프로필·기준 해시를 만들고 테스트 3개 실패를 확인한다. 기존 세션은 덮어쓰지 않는다. `start --public-relay`를 사용자가 실행하면 기존 서버가 원본 프로젝트의 제3자 공개 Cloudflare 중계로 연결된다. 실제 홈/저장소 대신 샘플 하나만 공개하며 기존 에이전트 상태와 분리한다. URL은 토큰을 포함하므로 앱 설정 밖에 공유하지 않는다.

모델은 새 확인 코드를 실제로 읽고 소스의 지정 연산자 하나만 바꾼다. `check`는 테스트·파일 집합 불변과 정확한 수정 내용을 확인한 다음에만 Node 테스트를 실행한다. E1_LOCAL_CHECK_OK만으로 모델의 행동을 증명하지 않으며 실제 도구 호출·재읽기와 대조해야 E1 통과다. 상태 분리는 OS 샌드박스가 아니다.

## 정책과 문서 기준
파일 도구는 기본 읽기 전용이며 편집용 프로필만 쓰기를 명시한다. E1은 셸/프로세스/Skills/하위 MCP/checks를 비활성화한다. 이름 필터는 비밀 내용 탐지가 아니다. Docker run_check는 별도 사본을 사용하지만 기존 셸/하위 MCP를 자동 격리하지 않는다.

**Git의 이 문서와 진행표가 기준이다.** 이번 보조 도구 9개는 E0 전체 재실행이나 실접속 성공이 아니다. src·기존 검증 실행기·의존성은 유지했다. [E1 준비 검증](validation/e1-preparation-local.json). CI는 한도 초과로 보류, PR Draft 유지. 이 응답에서 계정 연결·중계 시작·배포·main 병합은 수행하지 않았다. MIT 고지를 유지한다.
