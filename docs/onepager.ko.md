`ChatGPT → MCP → 공통 코어 → 파일 / Git / 검사 / 전문 도구`

## E0 결과와 증거 범위
사용자가 `d5b4ea9`에서 `88f455c`로 fast-forward한 뒤 실행한 로그에 `typecheck`, `build`, `full-tests`, `mcp-smoke` 및 `MINIMUM_LOCAL_OK (Docker and live ChatGPT not tested)`가 포함됐다. 원격 `88f455c5c69945bdcb7bd6cda23e9a6dbaceb839`의 실행기에서 모든 요청 단계 성공 후에만 이 표시를 출력함을 대조했다.

**사용자 제공 실행 결과를 근거로 E0를 통과로 기록한다.** 이번 응답에서 재실행한 결과나 GitHub CI 결과가 아니다. 원본 report.json·단계별 로그는 아직 받지 않았으므로 검사 개수/skip 수, 도구 버전, dirty 작업 트리 및 의존성 버전 일치는 확정하지 않는다. 이전 테스트 수를 합산하지 않는다. [현재 결과 기록](validation/e0-macos-user-report.json)

## 실행 정책과 최소 검증
파일 도구는 기본 읽기 전용이다. 편집용 프로필은 쓰기를 명시하고 셸/프로세스/Skills/외부 MCP는 끈다. E0는 실제 설치 SDK와 stdio 서버로 읽기 전용 거부, 민감 파일 비노출, 소스만 수정, 같은 테스트의 실패→성공, 오래된 해시 patch 거부를 검사한다. 성공은 해당 로컬 경로의 검증이며 실제 ChatGPT 모델의 선택·승인 흐름까지 보장하지 않는다.

`run_check`는 운영자 설정의 정확한 검사 이름만 받는다. 별도 사본을 로컬 Docker에 전달하고 원본 writeback·자동 pull·호스트 fallback은 없다. 실제 컨테이너 격리와 정리는 E0-D가 통과해야 검증된다. **기존 셸·하위 MCP는 자동 격리하지 않는다.** [실행 안내](minimum-verification.ko.md)

## 다음 순서와 문서 기준
파일-only E1을 우선하고 명령 실행이 필요할 때 E0-D를 별도로 수행한다. E1은 비밀정보 없는 샘플만 대상으로 하며 실제 계정 연결·공개 중계 실행은 따로 다룬다. 불필요한 재설치·E0 반복 실행 없이 확보한 결과를 유지한다.

**Git의 이 문서와 진행표가 기준**이다. 이번 갱신은 문서만 변경하며 검증 대상 실행 코드는 유지한다. CI는 사용자 확인 한도 초과로 보류, PR은 Draft다. main 병합·공개 터널·계정/과금 변경·이미지 다운로드·배포는 수행하지 않는다. 이름 필터는 내용 비밀 탐지기나 OS 격리가 아니다. MIT 고지를 유지한다.
