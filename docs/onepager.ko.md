## 목표와 구조
ChatGPT가 판단하고 포크가 실행·권한·기록을 맡는다. 기능 모듈은 내부 함수·기존 CLI·필요한 하위 MCP를 선택한다. 별도 서버나 모델을 의무화하지 않는다.

`ChatGPT → MCP → 공통 코어 → 파일 / Git / 검사 / 전문 도구`

## 단계·할 일·현재 위치
| 단계 | 수용 기준 | 상태 |
|---|---|---|
| M1·M2a | 모듈·CLI/Git·프로필·샘플 | 원격 구현, 기존 사용자 E0 근거 유지 |
| M2b-01/02 | 시작/reload·읽기/쓰기·민감 경로·하위 MCP 정책 | 원격 구현. 내용 비밀 탐지기나 OS 격리가 아님 |
| E0·E1 | 로컬 최소 통합·실제 ChatGPT 파일 편집 대조 | 이전 실행 코드의 사용자 제공 근거 기준 통과 유지 |
| M2b-03 / E0-D | Docker 사본 검사·실제 격리/타임아웃 정리 | 어댑터 구현, 실제 Docker 미검증·맥 필요 구간 보류 |
| M2C-01a | 공유 변경 큐·기준 해시·ID 중복 방지 | 이전 로컬 구현. 이번에도 회귀 검사, 원격 코드는 미반영 |
| M2C-02a | 영속 ID 예약·성공 영수증·중단 후 재실행 차단 | **로컬 구현·실제 강제 종료 검사 완료.** Workspace에 선택적으로 주입하는 라이브러리이며 서버 설정에는 아직 미연결 |
| M2c 잔여 | 서버 연결·교차 프로세스 파일 잠금·운영 복구 | 미완료. 같은 ID 예약과 다른 ID의 파일 충돌 제어는 다름 |
| M3-00 | 영속화 비용의 로컬 기초 측정 | 4 KiB 편집 100회씩 측정. 전체 ChatGPT/MCP 지연은 미측정 |

## 이번 결과
새 복구 29개와 이전 M2c/회귀 62개를 같은 실행에서 검사해 **91개 통과, 실패·취소·건너뜀 0**. 실제 Node 자식 프로세스를 변경 전, 변경 후/완료 기록 전, 완료 기록 후에 SIGKILL하고 재실행을 검사했다. 앞의 두 경우는 결과 미확인으로 거부하며, 완료 기록이 있는 경우는 과거 영수증만 반환한다. 여섯 프로세스의 동일 ID 요청은 실제 효과 한 번이었다.

이 컨테이너의 4 KiB 파일 편집 중앙값은 메모리 기록 0.901ms, 영속 기록 2.323ms였다. 파일 준비와 확인은 측정 구간 밖이며 순서를 번갈아 비교했다. 전원 장애·사용자 맥·네트워크/MCP·모델 지연이나 실제 개발 과제 속도로 일반화하지 않는다. [검증·측정 기록](validation/m2c-recovery-local.json)

## 반영 상태와 다음 관문
**새 실행 코드는 검토용 로컬 보관본에만 있다.** 이전 코드 업로드 보안 차단을 재시도하거나 우회하지 않았다. 이번 Git 변경은 문서·검증 기록뿐이며 기존 원격 실행 코드와 사용자 E0/E1 근거를 유지한다. 새 코드에 E0/E1 통과를 자동 부여하지 않는다.

다음은 허용된 코드 반영 경계 확인, 명시적 서버 설정/SDK 연결, 새 코드의 전체 의존성 검사다. 실제 Docker E0-D와 새 코드 macOS 검증은 별도다. 미완료 기록을 삭제하거나 새 ID로 자동 재실행하지 않는다. [복구 계약·한계](m2c-recovery-design.ko.md)

Git 문서가 기준이다. 사용자가 밖에 있는 동안 맥 명령·계정 조작·설치를 요구하지 않는다. PR Draft 유지; CI 재실행/과금·공개 중계·배포·main 병합 없음. MIT 고지를 유지한다.
