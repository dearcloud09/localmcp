## 목표와 구조
ChatGPT가 판단하고 포크가 로컬 실행·권한·기록을 담당한다. 기능 모듈은 내부 함수·기존 CLI·필요한 하위 MCP를 사용한다. 모듈화가 별도 서버나 추가 모델을 뜻하지 않는다.

`ChatGPT → MCP → 공통 코어 → 파일 / Git / 검사 / 전문 도구`

## 확보한 E0 근거
사용자의 `88f455c` 갱신 후 로그에서 네 단계와 MINIMUM_LOCAL_OK를 확인하고 해당 실행기와 대조했다. 사용자 제공 결과이며 어시스턴트 재실행·GitHub CI가 아니다. 원본 report.json·단계별 로그는 미수신이므로 개수/skip·버전·dirty 상태·설치 버전 일치는 확정하지 않는다. [E0 기록](validation/e0-macos-user-report.json)

## E1 결과와 근거 범위
사용자가 전달한 새 세션의 답변은 파일 전용 권한 확인, 세 파일 읽기, edit_file 한 번으로 `return a - b` → `return a + b`, 같은 세 파일 재읽기를 보고했다. 후속 로컬 출력은 E1_LOCAL_CHECK_OK, tests=3, pass=3, changedFiles=[calculator.mjs], testFileUnchanged=true를 보고했다. 두 보고의 확인 코드 원문이 일치하고, 개행 없는 UTF-8 SHA-256도 이전 기록과 일치함을 계산해 확인했다.

**이 두 사용자 제공 근거를 결합해 파일-only E1의 최소 수용 기준을 통과로 기록한다.** 원시 MCP 호출·승인 기록·맥 파일을 이 대화에서 직접 확인한 독립 감사는 아니다. 붙여넣은 로컬 JSON을 원본 evidence 파일 업로드로 표시하지 않는다. chatgptActorVerified=false는 로컬 검사 단독으로 편집 주체를 판별하지 않는다는 뜻이며 그대로 보존한다. [최종 E1 결과](validation/e1-local-check-user-report.json) · [이전 수행 보고](validation/e1-chat-session-user-report.json)

## 다음 순서와 정책
파일-only E1은 종료하며 재설치·E0 반복·샘플 재생성·재편집을 요구하지 않는다. 테스트 앱과 에이전트의 종료 여부는 별도로 확인되지 않았으므로 종료 완료로 기록하지 않는다. 다음 명령 실행 관문은 실제 로컬 Docker와 검토한 이미지로 E0-D를 수행하는 것이다. 이 파일 편집 테스트는 일반 코딩 성능이나 명령 실행의 격리·복구·지연을 검증하지 않는다.

파일 도구는 기본 읽기 전용이며 편집용 프로필만 쓰기를 명시한다. E1은 셸/프로세스/Skills/하위 MCP/checks를 끈다. 이름 필터는 비밀 내용 탐지나 OS 격리가 아니고 Docker run_check는 기존 셸/하위 MCP를 자동 격리하지 않는다.

**Git의 이 문서와 진행표가 기준이다.** 이번 변경은 문서와 결과 기록뿐이며 검증한 실행 코드는 유지한다. 확인 코드는 원문 대신 해시만 저장하고 접속 URL/토큰·개인 경로는 올리지 않는다. CI는 한도 초과로 보류, PR Draft 유지. 배포·main 병합·계정/과금 변경·이미지 다운로드는 하지 않는다. MIT 고지를 유지한다.
