## 목표와 구조
ChatGPT가 판단하고 포크가 로컬 실행·권한·기록을 담당한다. 기능 모듈은 내부 함수·기존 CLI·필요한 하위 MCP를 사용한다. 모듈화가 별도 서버나 추가 모델을 뜻하지 않는다.

`ChatGPT → MCP → 공통 코어 → 파일 / Git / 검사 / 전문 도구`

## 확보한 E0 근거
사용자의 `88f455c` 갱신 후 로그에서 네 단계와 `MINIMUM_LOCAL_OK (Docker and live ChatGPT not tested)`를 확인하고 해당 실행기와 대조했다. 사용자 제공 결과이며 어시스턴트 재실행·GitHub CI가 아니다. report.json·단계별 로그는 미수신이므로 개수/skip·버전·dirty 상태·설치 버전 일치는 확정하지 않는다. [E0 기록](validation/e0-macos-user-report.json)

## E1의 현재 근거와 마지막 관문
사용자는 앱 생성·연결 성공에 이어 새 ChatGPT 세션의 답변을 전달했다. 답변은 workspace=project, 파일 읽기/쓰기 허용, 셸·프로세스 비활성 및 Skills/하위 MCP/availableChecks가 빈 상태에서 세 파일을 읽고 edit_file 한 번으로 `return a - b`를 `return a + b`로 변경한 뒤 재읽었다고 보고한다. 수정 후 44바이트와 테스트/확인 코드 불변도 보고했지만 테스트는 실행하지 않았다고 명시한다.

**이는 사용자가 전달한 다른 세션의 수행 보고다. 이 대화에서 실제 도구 호출이나 맥 파일을 직접 관찰한 결과로 표시하지 않는다.** 보고된 확인 코드는 후속 로컬 출력과 대조하며, Git에는 원문 대신 UTF-8 문자열(개행 제외)의 SHA-256만 기록한다. [수행 보고 기록](validation/e1-chat-session-user-report.json)

[실연결 안내](e1-live-chatgpt.ko.md)에 따라 에이전트를 종료하고 `node scripts/e1-session.mjs check`를 실행한다. 파일 집합·테스트/README/확인 코드 불변 및 정확한 한 연산자 수정을 검사한 뒤 고정 테스트 3개가 통과해야 E1_LOCAL_CHECK_OK가 나온다. 로컬 확인 코드와 새 세션의 확인 코드를 대조해야 하며, 로컬 파일만으로 편집 주체를 증명할 수 없어 chatgptActorVerified=false는 정상이다. 새 세션 재생성·재편집·재설치·E0 반복은 요구하지 않는다.

## 정책과 문서 기준
파일 도구는 기본 읽기 전용이며 편집용 프로필만 쓰기를 명시한다. E1은 셸/프로세스/Skills/하위 MCP/checks를 비활성화한다. 이름 필터는 비밀 내용 탐지가 아니고 상태 분리는 OS 격리가 아니다. Docker run_check는 기존 셸/하위 MCP를 자동 격리하지 않는다. 연결 URL은 접속 토큰을 포함하므로 공유하지 않는다.

**Git의 이 문서와 진행표가 기준이다.** 이번 변경은 문서와 사용자 수행 보고만 반영하고 실행 코드는 유지한다. [E1 준비 검증](validation/e1-preparation-local.json). CI는 한도 초과로 보류, PR Draft 유지. 계정/비용 변경·배포·main 병합은 하지 않는다. MIT 고지를 유지한다.
