# LocalMCP 기반 모듈형 코딩 실행환경 — 1pager

**기준일:** 2026-09-18 · **기반:** `daodao97/localmcp@fff33cfb5249be914ec7bab54455e793c1617321` · **단계:** 첫 구현(M1)

## 목표
ChatGPT가 로컬 프로젝트를 읽고 수정하고 테스트할 수 있도록 LocalMCP를 포크한다. 모델은 판단을 담당하고, 포크는 실행 정책·작업 기록·결과 전달을 담당한다. 개발 기능은 교체 가능한 모듈로 분리하되, 모든 모듈을 별도 CLI나 MCP 서버로 만들지는 않는다.

## 설계 결정
`ChatGPT → MCP 입구 → 공통 실행 코어 → 기능 모듈 → 내부 함수 / 기존 CLI / 선택적 하위 MCP`

코어는 도구 등록, 입력 검증, workspace 선택, 기능 활성화 정책, 호출 결과·오류·실행 기록을 관리한다. 파일 편집은 내부 코드, Git·테스트·빌드는 기존 CLI를 우선 재사용한다. 하위 MCP는 전문 기능이 필요할 때만 연결한다. 자주 쓰는 기능은 모델이 바로 호출하게 하고, 통신 계층·추가 모델·의존성을 불필요하게 늘리지 않는다.

## 완료 기준
공통 코어를 통해 각 모듈이 호출되고, 잘못된 입력·비활성 기능이 실행 전에 거부되어야 한다. Git 어댑터가 실제 임시 저장소에서 작동해야 한다. 파일 권한·출력 문자 회귀 테스트가 통과해야 한다. 원본 의존성이 확보되면 전체 타입 검사·테스트·빌드를 실행하고, 확보되지 않으면 독립 모듈 검증과 전체 통합 미검증을 분리해 보고한다. 실제 ChatGPT 연결 성공은 별도 현장 검증으로 남긴다.

## 후속 단계와 범위 밖
**M2:** 프로젝트 한정 초기 설정, 일관된 권한 경계·격리 실행, 수정 충돌·작업 복구·감사 기록의 영속화. **M3:** 실제 과제로 최초/반복 호출, 오류·재시도, 전체 완료시간을 비교한 뒤 배치 처리·전문 도구를 추가한다. 자체 IDE·자체 언어 서버·다중 에이전트·브라우저 자동화·자동 배포는 이번 범위 밖이다. M1의 기능 플래그·검증·로그를 OS 샌드박스나 완성된 보안 경계로 간주하지 않는다.

## 실행·배포 경계
업스트림과 기존 계정 설정은 변경하지 않는다. 원격 포크·push는 인증된 쓰기 경로가 있을 때만 수행하고, 그 경로가 없으면 원본 기준 작업본·패치·적용 절차를 제공한다. 공개 터널 시작, 실제 홈 디렉터리 연결, 토큰 생성·공유, 패키지 배포는 자동 실행하지 않는다. 원본 MIT 고지를 유지한다.
