## 이번 로컬 구현 범위
공유 경로 큐는 같은 파일·상하위 경로의 변경을 직렬화하고 파일 이동은 양쪽 경로를 예약한다. 서로 무관한 파일은 병렬 진행한다. Workspace의 일반 쓰기·텍스트 편집·행 patch·디렉터리 생성/삭제/이동이 같은 큐를 사용한다. 같은 프로세스의 여러 Workspace 객체가 조정기를 공유한다.

텍스트 편집과 patch는 읽기·기준 해시 대조·수정·교체를 같은 임계 구간에서 수행하고, 최종 교체 직전에 해시와 메타데이터를 다시 확인한다. 읽기 기본 응답은 유지하며 선택적으로 정확한 UTF-8 SHA-256/바이트 수를 반환한다. BOM/CRLF 보존과 비정상 UTF-8 거부도 검사했다.

선택 작업 ID는 기준 해시를 요구한다. 같은 ID/인자의 실행 중 요청과 재전송은 한 결과를 공유하고, 다른 인자·도구·파일에 대한 ID 재사용은 거부한다. 실패한 ID는 자동 재실행하지 않는다. 결과 재전달 표시는 과거 작업의 영수증이지 현재 파일 상태 확인이 아니다. 최대 1,024개 기록에서 새 ID를 거부하고 자동 만료/축출하지 않는다.

이는 **현재 로컬 검토본의 설계와 검사 결과**이며 원격에 제공되는 기능으로 표시하지 않는다. 신규 소스·테스트는 대화 보관본의 proposed-source에 있고, source-only 패치와 manifest에 기준 파일 해시를 기록했다. 자동 적용·업로드·서버 시작 도구는 포함하지 않았다.

이전 Workspace의 읽기 교차 순서를 고정한 대조에서 같은 해시의 두 패치는 모두 성공했고, 로컬 수정본은 하나만 성공하고 하나를 충돌로 거부했다. 동일한 편집 요청 20개는 한 번만 적용됐다. 교체 직전 외부 변경을 삽입한 검사에서는 외부 내용을 유지하고 임시 파일을 정리했다. 이 검사는 실제 임시 파일을 사용하지만 SDK/macOS 검증과 다르다.

신규 실제 config/Zod/SDK 검사 5개는 작성/문법 검사만 수행했다. git 접근은 github.com DNS 실패, SDK·Docker는 현재 환경에서 찾지 못했다. 전체 checkout이 아닌 부분 소스 fixture로 검사했다. 전체 원본 의존성 check/build/test·새 코드 E0/E1·macOS/Windows·실제 Docker는 미실행이다. [실행 근거 및 차단 기록](validation/m2c-mutations-local.json)

## 다음 관문과 한계
먼저 원격 코드 반영 경계를 해결하고 그 뒤 새 코드의 전체 통합 검증을 수행해야 한다. 실제 Docker E0-D는 별도 로컬 환경이 필요하므로 보류한다. 사용자가 밖에 있는 동안 추가 실행·계정 변경·이미지 설치를 요구하지 않는다.

잠금과 중복 기록은 단일 Node 프로세스이며 외부 에디터·셸·하위 MCP는 참여하지 않는다. 최종 확인과 OS rename은 원자적으로 묶여 있지 않고, 재시작하면 ID 기록이 사라진다. 영속 exactly-once·교차 프로세스·롤백·다중 파일 트랜잭션을 보장하지 않는다. 일반 write_file에는 버전/ID 계약을 아직 추가하지 않았다.

URL/토큰·개인 경로·확인 코드 원문을 새 기록에 넣지 않는다. CI 한도·과금·공개 중계·배포·main 병합은 변경하지 않고 PR Draft를 유지한다.
