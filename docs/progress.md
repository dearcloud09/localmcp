## 이번 변경과 검증

신규 구현은 `scripts/lib/project-profile.mjs`(정책·파일 생성), `scripts/project-profile.mjs`(CLI), `test/project-profile.test.mjs`다. Node 기본 모듈만 사용하며 새 npm 의존성을 추가하지 않았다. 기존 M1 `src/`와 CLI 실행기는 수정하지 않았다.

- 이 실행환경에서 `node --test test/project-profile.test.mjs`: 28개 통과, 실패/취소/건너뜀 0.
- `npm run test:profile`로 같은 신규 검사 경로도 28개 통과. 별도 28개를 더 검증한 것으로 합산하지 않는다.
- 실제 하위 Node 프로세스로 CLI init/doctor와 샘플 실패→성공을 검증했다. 샘플 테스트 파일은 바꾸지 않았다.
- 새 코드·테스트의 Node 문법 검사 통과. 현재 환경: Linux / Node 22.16.0 / npm 10.9.2.
- 첫 실행에서 중첩 `node --test`가 상위 러너의 `NODE_TEST_CONTEXT`를 상속하면 검사를 건너뛰는 현상을 발견했다. 하위 검사 환경에서 이를 제거하고 실제 3개 실패/3개 성공을 모두 확인하도록 고쳤다.
- 새 `npm test` 전체 경로·SDK/Worker·macOS/Windows·실제 ChatGPT 연결은 미실행이다. 기존 M1의 64개 통과와 이번 28개를 합쳐 전체 92개 통과라고 표시하지 않는다.
- 전체 복제 시 `github.com` DNS 해석에 실패했다. 연결된 GitHub로 원격 파일을 읽었으나 전체 clone이나 원본 의존성 설치를 완료한 것은 아니다.

검증 세부: [validation/m2a-local.json](validation/m2a-local.json). 명령과 사용 경계: [M2a 가이드](m2a-project-profile.ko.md).

## 자율 진행 범위

문서·코드·회귀 테스트·작업 브랜치의 커밋·PR 기록을 함께 갱신한다. 기존 승인 범위 내 가역적인 개발은 매 단계 재승인을 요구하지 않는다. 다만 사용자 맥에서의 실행, 계정 연결, 공개 터널/토큰, 비용 변경, main 병합은 완료로 가장하거나 대신 실행하지 않는다.

M2a 도구는 새 파일 전용 프로필의 **사전 점검**이다. 현재 `src/config.ts`, `src/index.ts`, `src/agent.ts`의 기본 동작을 대체하지 않고, 검사 후 파일 변경이나 악의적인 로컬 프로세스에 대한 보안 경계도 제공하지 않는다. 이 잔여 문제를 M2b에서 다룬다.
