## 이번 로컬 구현: M2C-02a
`DurableMutationJournal`은 모든 지정 workspace와 겹치지 않는 소유자 전용 디렉터리를 사용한다. 시작 기록이 동기화된 뒤 실제 변경 콜백을 실행한다. 완료 기록에는 상대 경로·바이트 수·전후 해시·편집 수만 저장하며 원문 소스·수정 내용·예외 메시지는 기록하지 않는다. 해시는 암호화가 아니며 낮은 엔트로피의 내용은 별도 주의가 필요하다.

같은 저장소/ID를 다시 받으면 성공 기록은 과거 영수증으로 반환한다. 다른 인자의 ID 재사용, 실패한 기록, 진행 중인지 중단됐는지 판별할 수 없는 기록, 손상된 기록은 자동 실행하지 않는다. 성공 기록을 현재 파일 상태의 증명으로 쓰지 않는다.

새 ID 할당은 짧은 디렉터리 잠금으로 조정하고 실행 전에 시작 기록을 기록한다. 같은 journal을 공유하는 여섯 Node 프로세스의 동일 ID에서 한 번만 효과가 발생했다. 다른 ID의 파일 잠금은 이전 M2c처럼 프로세스 내부 범위다. 할당 중 죽어서 남은 잠금은 임의로 훔치거나 지우지 않으며 운영자 검토가 필요하다. 기본 1,024개 기록을 자동 축출하지 않는다.

로컬 Workspace에 journal 인터페이스를 선택적으로 주입하고 실제 editText/applyEdits로 재개를 검사했다. 기본 메모리 journal은 유지한다. **실제 서버의 config/selectWorkspace/MCP 경로가 자동으로 이 기능을 사용하지는 않는다.**

## 실제 검증
Linux / Node 22.16.0 / TypeScript 5.8.3 / @types/node 25.1.0 / 실제 테스트 UID 1000. 부분 소스 fixture이며 전체 clone이 아니다.

한 Node 테스트 실행에서 **91개 통과, 실패·취소·건너뜀 0**: 새 journal/Workspace 25 + 실제 프로세스 강제 종료·동시성 4 + 이전 M2c 큐/Workspace 37 + 기존 CLI/Git/파일/프로세스 25. 같은 소스 부분집합의 엄격한 TS 검사도 통과했다.

- 실제 자식 프로세스를 효과 전 SIGKILL: 효과 0, 재개 시 미확정, 재실행 거부.
- 효과 기록 후 완료 journal 전 SIGKILL: 효과 1, 재개 시 미확정, 재실행 거부.
- 완료 journal 후 SIGKILL: 성공 영수증 재전달, 효과 여전히 1.
- 여섯 별도 프로세스의 동일 ID: 실제 효과 1. 같은 인스턴스 요청 20개도 실제 콜백 1.
- 메모리 journal을 새 객체로 교체한 대조군은 두 번 실행, 영속 journal 재열기는 한 번만 실행.
- 권한을 없애 완료 기록 쓰기를 실패시킨 검사: 결과 미확인, 자동 재실행 없음. 임시 테스트 디렉터리만 변경했다.
- 기록 잘림/체크섬 손상·링크·권한 확대·저장소 교체·용량 제한·작업 ID 충돌 검사.

초기 capacity 테스트는 테스트용 잠금 시간 50ms 때문에 용량 오류 대신 잠금 시간초과를 만났다. 정상 fixture를 실제 기본값 2000ms로 맞췄고 용량/효과 개수 조건은 그대로 유지했다. 남은 잠금 검사는 별도로 50ms를 사용한다. 실행을 건너뛰거나 assertion을 제거해 통과시키지 않았다.

[이번 기계 판독 기록](validation/m2c-recovery-local.json)과 대화의 검토 패키지에 실제 로그·소스 해시·microbenchmark 원시 표본을 보관한다. 기존 SDK 검사 5개, 신규 서버 연결, 전체 pinned check/build/test, macOS/Windows, Docker, 실제 ChatGPT는 이번에 수행하지 않았다. GitHub Git와 npm registry HTTPS는 DNS 실패했고 Docker 실행 파일은 없었다.

## 속도 측정의 범위
4 KiB 파일 editText를 메모리 journal과 영속 journal 각각 10회 예열 후 100회 측정했다. 순서를 번갈아 실행했고 파일 준비·결과 assertion은 타이머 밖이다. 중앙값/p95: 메모리 0.901/1.290ms, 영속 2.323/3.409ms. 성공 영수증 재전달은 0.554/0.840ms지만 새 편집과 다른 동작이므로 편집 속도 개선으로 비교하지 않는다.

전체 ChatGPT/MCP 지연, 사용자 맥 성능, 실제 디스크 전원 장애 내구성으로 일반화하지 않는다. 추가 파일 동기화의 비용을 숨기지 않고 좁은 기준선을 확보한 결과다.

## 유지한 과거 근거와 다음 관문
[E0](validation/e0-macos-user-report.json)는 사용자 macOS의 88f455c 최소 검증 성공 보고다. [E1](validation/e1-local-check-user-report.json)은 다른 ChatGPT 세션의 답변과 로컬 3/3·확인 코드 일치에 근거한 파일-only 통과다. 원시 도구 기록·승인·정확한 실행 버전을 이 대화에서 직접 감사한 것은 아니며 chatgptActorVerified=false는 보존한다.

[이전 M2c](validation/m2c-mutations-local.json)의 로컬 62개는 이번 91개 중 다시 실행한 부분집합이다. 과거 수치를 더해 새로운 전체 검사 수로 표시하지 않는다. 원격 실행 코드가 그대로이므로 기존 성공 근거는 유지하지만 새 로컬 코드에 E0/E1 통과를 부여하지 않는다.

다음은 허용된 코드 반영 경계 확인과 서버 설정/SDK 연결, 새 변경의 전체 통합 검증이다. 실제 Docker·사용자 맥은 별도 검증이다. 잠금/기록만으로 OS 원자적 파일+로그 트랜잭션, 외부 에디터 경합 방어, 자동 롤백, 프로세스 부활을 보장하지 않는다. SIGKILL 검사는 전원 장애가 아니다.

사용자가 밖에 있는 동안 추가 명령이나 계정 조작을 요구하지 않는다. CI 비용·공개 중계·계정/과금·이미지 설치·배포·main 병합 없음. 이전 업로드 차단의 우회나 재시도 없음. Git 기준 문서와 PR에는 로컬/원격 구현 상태를 구분한다.
