## 현재 상태 — 수정 후 M2c 로컬 검사 성공 보고, 코드 push 대기
이 갱신의 원격 기준은 `5cc0c7c3624f316473e3949e76c4cd6f77505850`다. 사용자가 검사용 worktree에서 루트 이동 검사 순서 수정을 적용하고 `M2C_LOCAL_CHECKS_OK`를 제공했다. 안내한 순차 블록이 끝났다는 사용자 보고를 근거로 새 코드의 로컬 최소 검사와 별도 E1 보조 검사를 통과로 기록한다. 이번 원격 변경은 문서·결과 기록뿐이며 새 M2c 실행 코드는 아직 원격에 없다.

## 최신 결과의 해석
순차 블록은 민감 경로 검사, verify:minimum, 별도 e1-session 검사를 차례로 실행하고 마지막 성공 표시를 출력한다. verify:minimum은 타입 검사 → 빌드 → 전체 npm test → 설치된 SDK와 빌드 서버의 stdio 파일 smoke를 포함한다. 이번 완료 판정은 사용자 제공 최종 표시와 이전에 전달한 블록에 근거한다. 어시스턴트가 맥에서 재실행한 결과나 CI 결과는 아니다.

최신 report.json·전체 로그는 아직 받지 않았다. 수정 후 정확한 전체 검사 수·skip 수·Node/npm 버전·작업 트리 바이트를 추정하지 않는다. 직전 실패 실행은 darwin / Node v23.11.0 / revision=7a11495 / dirtyWorkingTree=true였으나, 이를 최신 실행에서 다시 확인했다고 쓰지 않는다. 기존 TS 335/336 로그는 수정 전 기록으로 남긴다.

별도 e1-session 검사는 준비/확인 보조 도구의 회귀 검사다. 실제 계정의 도구 선택·승인·파일 편집을 재수행한 E1은 아니며 실제 Docker도 요청하지 않았다. [최신 사용자 성공 기록](validation/m2c-local-checks-user-report.json)

## 보존한 실패·수정 이력
직전 실행은 타입 검사·빌드 성공, TS 검사 336개 중 335개 성공/1개 실패/취소·skip 0이었다. 유일한 실패는 `workspace-root movement and removal are refused`: 예상 /workspace root/, 실제 Path is outside workspace. 새 변경 큐가 목적지 ../new를 먼저 검사해서 기존 루트 이동 거부 메시지보다 범위 이탈 오류를 먼저 반환한 회귀였다. 이동을 허용한 결과는 아니었다.

그 실패 로그에도 mutation-integration 5개와 recovery-runtime-sdk 7개는 모두 성공 표시가 있었다. 실제 source-mode 자식 실행·강제 종료와 기존 HTTP/stdio/Worker/hot-reload 검사도 성공했다. 이 12개는 당시 335개의 부분집합이지 더할 숫자가 아니다.

수정은 공개 move 진입점의 출발지 루트 검사와 주석 두 줄이며 기존 내부 검사·잠금·목적지/민감 경로 정책과 기존 테스트는 유지했다. 이전 어시스턴트 Linux 검증은 168개 통과였으며 이번에 다시 실행하거나 사용자 전체 검사 수에 합산하지 않았다. [실패·수정 근거](validation/m2c-root-order-local.json)

## 다음 코드 반영 절차의 조건
사용자가 검증 후 코드를 추가 변경하지 않았다는 전제에서 진행한다. 작업 브랜치와 fetch/push 저장소를 확인하고, unstaged 변경이나 예상 밖 상태가 있으면 중단한다. 이미 준비된 패치와 root-order 수정을 커밋 대상으로 사용하며 git add .로 관련 없는 파일을 추가하지 않는다.

원격에는 사용자 worktree의 기준 뒤 문서 커밋이 추가되어 있다. 최신 원격을 fetch하고 공통 기준 이후 변경이 docs 아래에만 있는지 확인한다. 로컬 코드를 커밋한 다음 문서를 병합하고, 병합 전후 docs 이외의 트리가 동일해야 push한다. 원격에 실행 코드·테스트·의존성 변경이나 충돌이 있으면 자동 push/강제 push하지 않는다. 검증 이후 코드가 달라진 경우 그 변경에 필요한 검사를 다시 판단한다.

성공적으로 push하고 원격 코드를 대조하기 전에는 IG-04를 완료로 바꾸지 않는다. main 병합·배포가 아니라 기존 Draft PR의 작업 브랜치 갱신이다. 이전 소스 업로드 도구 차단은 여기서 재시도하지 않는다.
