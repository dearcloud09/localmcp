## 이번 변경: M2b-01a
- `src/core/runtime-policy.ts`: 필수 설정 읽기, 명시적 프로젝트 검증, 실행 환경변수의 권한 확대 금지.
- `src/config.ts`: 누락 설정과 홈 fallback 제거, 기본 셸/프로세스 비활성, Skills는 명시적 선택. 시작과 reload가 동일 검증을 사용.
- `src/index.ts`: 자동 홈 설정 생성 제거. 기존 init은 검증만 하며 start/reload 전에 검증. stop/status는 잘못된 설정에서도 사용 가능.
- `src/agent.ts`: 상태/등록/네트워크보다 설정 검증을 먼저 수행. `src/launch.ts`도 자격증명 생성 전에 검증하고 quick 상태를 프로젝트 밖 `~/.localmcp/quick`에 둠.
- 기존 lifecycle·stdio·HTTP·MCP·Worker·hot reload 테스트의 설정/작업 폴더를 분리. 기존 행위 검사는 유지하고 위험한 reload 후보 거부를 추가.
- 새 정책 단위 검사 및 실제 config/실행 진입점 통합 검사를 추가. **통합 검사 파일은 작성했지만 이 환경에서 실행하지 못했다.**
- 예제 설정에서 홈 전체/셸 기본 활성화를 제거. 기존 사용자 파일은 덮어쓰지 않음.

## 실제 검증과 제한
Linux / Node 22.16.0 / TypeScript 5.8.3에서 정책 및 기존 독립 모듈의 strict 타입 검사 통과. 정책 24개와 기존 독립 모듈 43개를 **같은 Node 테스트 명령으로 실행하여 67개 통과**, 실패/취소/건너뜀 0. 전체 앱 테스트 수는 아니다. 변경 소스·테스트의 문법 검사를 별도로 수행했다.

Git clone은 github.com DNS 실패, npm ping은 registry.npmjs.org DNS 실패. 전체 checkout과 원본 의존성이 없어 현재 전체 check/build/test, SDK/Worker·실행 진입점 통합, macOS/Windows, 실제 ChatGPT는 미검증이다. 테스트 더블을 실제 SDK 검증으로 표시하지 않는다. 이전 M1 64개·M2a 28개와 이번 67개를 합산하지 않는다.

검증 데이터와 소스 식별: [validation/m2b-policy-local.json](validation/m2b-policy-local.json). 이전 M2a 기록은 [validation/m2a-local.json](validation/m2a-local.json)에 유지한다. 적용 규칙: [M2b 안내](m2b-runtime-policy.ko.md).

## 남은 경계
M2b-01a는 기본 실행 진입점/설정 로더의 정책이다. 직접 라이브러리를 호출하는 임베딩이나 악의적인 같은 OS 사용자에 대한 보안 경계가 아니다. workspace 내부 비밀 파일, 명시적으로 켠 셸·외부 MCP, 실행 중 프로세스의 권한 회수, OS 격리는 별도 작업이다. 잘못된 hot reload는 마지막 유효 설정을 유지하며, 이것이 즉시 권한 회수를 의미하지는 않는다.

자율 진행은 작업 브랜치의 코드·문서·검증 기록 갱신까지 수행한다. 사용자 맥의 명령 실행·계정 연결·공개 터널·과금·main 병합은 대신 완료했다고 주장하지 않는다.
